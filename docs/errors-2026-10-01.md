Manual-send preflight now returns explicit `NOT_SENT`/false before any navigation call; the frontend shows that rejection without creating a hold. Genuine post-dispatch failures remain held.

The user-approved one-address Google check returned only partial locality/state results with approximate coordinates. Existing street/house-number safeguards correctly reject them. Those safeguards and apartment-first geocoding are preserved. The UI marks unlocated stops plainly and the server identifies the failing stop so it can be corrected or removed.

## Command review

The read-only command review completed naturally. Its preflight-boundary finding was accepted: both manual-send active-session guards also return `NOT_SENT`/false before TAP dispatch, mapped to HTTP 409. No generic exception around dispatch is classified as not sent. Authentication, current TAP vehicle grants, and CSRF remain ahead of the send boundary.

The review also verified an existing limitation: manual uncertainty holds live in browser `sessionStorage`, while TAP's durable command ledger deduplicates only the same idempotency key. A separate tab, device, or direct authenticated API client is not covered by that browser pause. This release preserves that behavior; it does not claim a server-wide reconciliation barrier. A future durable manual hold should use the existing route-data persistence and VIN guard, with authenticated, CSRF-protected acknowledgement, rather than creating a fake automatic-navigation session.
